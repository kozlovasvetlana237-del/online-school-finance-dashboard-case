# Аудит этапа 1

## Статус

Этап 1 финансового ядра реализован частично и проверен автоматическими тестами. Ветка: `codex/financial-core`.

## Исправленные проблемы

- разрозненные KPI заменены расчётами из исходных операций;
- добавлены периоды, продукты, бизнес-юниты, каналы, продажи, расходы, денежные операции и бюджеты;
- EBITDA рассчитывается из валовой прибыли и операционных расходов;
- конечные деньги рассчитываются как начальные деньги плюс чистый денежный поток;
- баланс проверяется без остаточной корректировки капитала;
- предоплата не признаётся выручкой до оказания услуги;
- план-факт обрабатывает нулевую базу как `null`, а интерфейс как `н/д`;
- положительное отклонение расходов не считается автоматически благоприятным;
- удалена логическая причина расхождения ДДС и ОПиУ: налог не начисляется без налоговой операции или обязательства.

Команда `npm test`:

Дополнительно пройдены `git diff --check` и синтаксическая проверка трёх JavaScript-модулей через `node --check`.

## Ограничения

- legacy inline JavaScript в `index.html` отключён условным guard и больше не выполняется; физическое удаление блока оставлено отдельной безопасной уборкой;
- CSS пока не вынесен полностью из inline-блока, в `styles.css` добавлен подключаемый слой совместимости;
- в демонстрационных данных нет отдельной налоговой операции, поэтому налоги равны нулю до реализации налогового обязательства;
- браузерная ручная проверка через локальный HTTP-сервер не выполнена из-за недоступности Python-исполняемого файла в среде;
- этапы 2-5 не реализованы: полноценный факторный анализ, rolling forecast, юнит-экономика, когорты, платёжный календарь и бюджетный контроль остаются следующими задачами.

## Запуск

Открыть `index.html` через GitHub Pages. Для тестов выполнить `npm test`. Для локального браузерного запуска нужен любой статический HTTP-сервер, потому что ES-модули могут блокироваться при открытии через `file://`.
