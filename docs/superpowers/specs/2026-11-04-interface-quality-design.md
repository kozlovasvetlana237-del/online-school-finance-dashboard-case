# Этап 5: качество интерфейса и тестирование

## Цель

Закрыть приёмочные критерии интерфейсного этапа без изменения уже согласованной финансовой модели.

## Объём

1. Вынести чистую логику чтения глобальных фильтров и преобразования темы в небольшой модуль.
2. Сохранить текущий русский интерфейс, светлую и тёмную темы, GitHub Pages и отсутствие обязательного сервера.
3. Добавить Node-тесты для UI-контракта: обязательные элементы, модульный скрипт, демо-маркировка, доступные значения фильтров и отсутствие опасных бесконечных расчётов.
4. Добавить проверки целостности демо-данных и критических финансовых равенств поверх существующих тестов.
5. Выполнить ручной браузерный smoke-тест: загрузка, KPI, вкладки, фильтры, тема, когортный переключатель, казначейский горизонт и редактирование бюджетного статуса.

## Архитектура

`js/ui-state.js` содержит только чистые функции `readFilterState(elements, data)` и `nextTheme(theme)`. `js/ui.js` использует их для рендера и подписок, а финансовые расчёты остаются в `financial-engine.js` и `analytics.js`. Тесты не требуют браузера и проверяют HTML и JavaScript как контракт приложения.

## Ограничения

- синтетические данные не выдаются за реальные;
- внешние зависимости и платные сервисы не добавляются;
- изменение финансовой формулы допускается только при воспроизводимой ошибке;
- после изменений все существующие и новые тесты должны проходить;
- итоговая проверка должна включать опубликованный GitHub Pages URL.

## Критерии готовности

- `npm test` проходит без ошибок;
- обязательные UI-элементы присутствуют в `index.html`;
- фильтры имеют безопасные значения по умолчанию;
- переключение темы не создаёт недопустимого состояния;
- опубликованная страница загружает модульный JavaScript и реагирует на основные элементы управления.
